# Pulse Mobile ↔ PulseDeck: API v1 (TLS)

Статус: **реализовано на стороне ПК, ждёт поддержки в Pulse Mobile.** API v0 (HTTP) работает
без изменений, пока в настройках ПК включён «Старый протокол без шифрования».

## Что меняется по сравнению с v0

| | v0 | v1 |
|---|---|---|
| Транспорт | HTTP, порт 8765 | **TLS 1.2+**, порт 8767 |
| Сертификат | — | самоподписанный, создаётся на ПК; телефон **закрепляет отпечаток** |
| Сопряжение | `POST /api/pair`, окно «Да/Нет» на ПК | `POST /api/v1/pair` с **6-значным кодом** с экрана ПК |
| Проверка связи | `GET /api/ping` | `GET /api/v1/info` |
| Остальные маршруты | `/api/<путь>` | `/api/v1/<путь>` — те же тела запросов и ответов |
| Ключи устройств | индивидуальные | **те же** (ключ из v0 действует и в v1) |
| Доступ | только локальная сеть | только локальная сеть |

## Поиск ПК (UDP 8766)

Запрос как в v0: широковещательный датаграммный пакет `PULSEPC?`. Ответ — JSON. В v1 добавлены
два поля; клиенты v0 их игнорируют:

```json
{"app": "PulsePC", "name": "DESKTOP-1", "port": 8765, "tls_port": 8767, "api": [0, 1]}
```

- `tls_port` есть, только если сервер v1 запущен.
- `api` — поддерживаемые версии. `[1]` и `"port": 0` означают, что старый протокол на ПК выключен.

## Сопряжение

1. Владелец ПК открывает «Телефон → Подключить по коду». ПК показывает код (6 цифр), порт и
   короткий отпечаток сертификата, например `CB9D BB10 52EF 2C38`.
2. Телефон подключается к `https://<ip>:<tls_port>` **без проверки цепочки сертификатов**
   (сертификат самоподписанный), читает сертификат сервера и вычисляет
   `SHA-256(DER)`.
3. Телефон показывает пользователю первые 8 байт отпечатка в том же формате и просит сверить с
   экраном ПК. Пользователь вводит код.
4. `POST /api/v1/pair`:
   ```json
   {"device": "Pixel 8", "code": "736084"}
   ```
   Ответ `200`:
   ```json
   {"ok": true, "token": "<ключ устройства>", "name": "DESKTOP-1", "api": 1}
   ```
5. Телефон сохраняет **ключ и полный отпечаток** (64 hex-символа). Все дальнейшие подключения
   к этому ПК обязаны предъявлять сертификат с тем же отпечатком; иначе — ошибка «Сертификат ПК
   изменился», без отправки ключа.

Ошибки сопряжения (`403`, JSON `{"ok": false, "error": "…"}`):
- код на ПК не запрошен или истёк (2 минуты);
- неверный код. После 5 неверных попыток код аннулируется, нужен новый.

Код одноразовый. Окно «Да/Нет» в v1 не используется: подтверждение — сам факт, что владелец
показал код.

**Почему нужна сверка отпечатка.** Без неё злоумышленник в той же сети может встать между
телефоном и ПК, перехватить введённый код и подключиться сам. Сверка первых 8 байт отпечатка
это исключает. Ещё лучше — QR-код с адресом, кодом и отпечатком на экране ПК (не реализован;
предлагается для следующей версии, когда клиент научится его сканировать).

## Запросы после сопряжения

Заголовок `Authorization: Bearer <ключ>` — как в v0. Пути: `/api/v1/` + путь из v0, например:

| v0 | v1 |
|---|---|
| `GET /api/status` | `GET /api/v1/status` |
| `POST /api/programs/{id}/run` | `POST /api/v1/programs/{id}/run` |
| `GET /api/player/state` | `GET /api/v1/player/state` |
| `POST /api/files/upload?name=…` | `POST /api/v1/files/upload?name=…` |

Коды ответов совпадают с v0: `401` — ключ неверен или отозван (нужно новое сопряжение),
`423` — ПК заблокирован, `403` — запрос не из локальной сети, `400` — ошибка в запросе
(текст в `error`), `500` — внутренняя ошибка без подробностей.

`GET /api/v1/info` (без ключа):
```json
{"ok": true, "app": "PulsePC", "api": 1, "pairing": false}
```
`pairing: true` — на ПК сейчас показан код.

## Переход

1. Pulse Mobile с поддержкой v1 при наличии `tls_port` использует v1, иначе v0.
2. Телефон, уже подключённый по v0, может перейти на v1 без нового сопряжения: ключ тот же,
   отпечаток закрепляется при первом подключении по TLS (с подтверждением пользователя).
3. Когда все телефоны перешли, владелец выключает «Старый протокол без шифрования».
   Маршруты v0 не удаляются из кода, пока не выйдет совместимая версия Pulse Mobile.

## Что проверено на стороне ПК

`tests/test_api_v1.py`: TLS-соединение с закреплённым отпечатком, сопряжение по коду, отказ
без ключа, отзыв ключа, одноразовость и срок действия кода, лимит попыток, совместимость ключей
v0/v1, неизменность v0, ответ на поиск по UDP.

## Добавлено для PulseDesk (Android), октябрь 2026

Все маршруты: `/api/v1/...` (TLS) и `/api/...` (v0); нужен токен, ПК не заблокирован.

| Метод | Путь | Тело / параметры | Ответ |
|---|---|---|---|
| GET | `/processes` | — | `{processes:[{pid,name,cpu,memory}]}`; cpu — % всего процессора за 0,3 с, memory — байты; до 300, самые нагруженные сначала |
| POST | `/processes/{pid}/kill` | — | `{message}`; системные процессы (`lsass.exe`, `csrss.exe`, `svchost.exe`…), PID ≤ 4 и сам PulseDeck → 400 |
| POST | `/files/mkdir` | `{path, name}` | `{path}` |
| POST | `/files/rename` | `{path, name}` | `{path}` |
| POST | `/files/delete` | `{path}` | `{message}`; только в Корзину Windows, никогда безвозвратно |

- Корень диска и относительные пути — 400. Недопустимое имя (`<>:"/\|?*`, `.`, `..`) — 400.
- WebSocket `metrics`: добавлены `cpu.per_core` (список %, по логическим ядрам) и `uptime` (секунды с загрузки).
- **Уровень доступа устройства** (`access` в `config/local_api.json`): `full` (по умолчанию, в том числе для старых записей) или `view`.
  - `view` разрешает только `GET` из `READ_WHEN_LOCKED`: `status`, `events`, `player/state`, `player/cover`, `display`.
  - Остальное — 403. Команды на WebSocket отклоняются с `error.code = "view_only"`.
  - Уровень меняется на ПК: экран «Телефон», столбец «Доступ».
